Why two loops

A Claude Code plugin, and its own marketplace.

Most agent workflows collapse design and construction into one conversation. The flywheel separates them, because they run at different speeds and answer to different things. Design is slow, converging, and full of open questions; construction is fast, parallel, and wants a settled target. Fusing them means either designing under build pressure or building against a design still moving.

So there are two loops, each with its own record and its own actors, and one place where work crosses from the first into the second.

outer loop

Design — an intent

One intent is one tracked change. Its task list is the frontier; the loop's job is burning fog into decisions, writing the destination into the design books, and handing settled slices on.

the coupling

The phase gate

Nothing crosses without your word. It is one approval covering a whole batch, taken on the cheapest channel that can carry it — not a meeting, and not one question per item.

inner loop

Construction — a bolt

One bolt is one construction iteration, tracking a registry of proposals from spec to merged across whatever repositories the work touches. Past the gate it runs without you.

Everything above the gate is design and produces records. Everything below it is construction and produces commits. The dotted edges are the only feedback paths: a finding that turns out to be a design problem goes back to dispatch rather than being fixed in place, and a landed handoff reports back so the intent can check its task off.

One rule does most of the work

Every file edit that is not a design record is construction, and leaves through the gate. Including edits to the repository the loop itself runs in.

Without that rule the design loop quietly grows a habit of making small fixes, and the record of why the code looks the way it does starts going missing. With it there is exactly one path out of design, and a handoff carrying a single proposal is a one-proposal bolt — the same path at its smallest size, not a shortcut around it.

Grey boxes are write scopes. A design session never writes a decision record and never checks its own task off — it reports, and the conductor promotes. A conductor never edits inside a session's directory. The books and the context map are the one scope two actors share, and that is deliberate: they are the destination, and both loops read them.

ActorLives as long asWrites
dispatchalways — one per org fleetnew intent changes, at the moment of triage, and nothing else

bolt conductorits boltthe bolt's proposal registry and tasks
spec / apply / testingone jobthe change and branch their registry row names

Dispatch is the only actor bridged to you. A question a bolt conductor cannot answer travels out through dispatch and the answer comes back to the conductor that raised it — never to a different actor, and never as an edit to that conductor's change.

Inside a bolt

Every row of the registry is in exactly one of these states.

stateDiagram-v2
  direction TB
  [*] --> to_spec
  to_spec : to-spec
  in_review : in-review

  to_spec --> specced : spec agent, validated
  specced --> in_review : independent reviewer
  in_review --> approved : verdict
  in_review --> to_spec : bounced — one round only
  approved --> building : apply agent, nested worktree
  building --> built : commit stage + merge gate
  built --> verified : batched acceptance on the bolt branch
  verified --> merged : full release gate
  merged --> [*]

Spec review is bounded to one round. A bounce is followed by a fix or by a re-spec from the decision record that settled it, and the result of either is built rather than read again — because further rounds converge on wording rather than on whether the thing can actually be built. What is bounded is reading; the merge gate, the acceptance suites and the release gate never relax.

Install

The repository is its own marketplace, so it is two commands.

/plugin marketplace add agentplot/flywheel
/plugin install flywheel@flywheel

Working on the flywheel itself

Both commands are bypassed while you are editing the plugin. Point Claude Code at a checkout and reload in place — no publish, no reinstall, no version bump between an edit and trying it. 

claude --plugin-dir /path/to/flywheel/main
/reload-plugins
